**Cline installs now use the current config layout, emit project-level skills, and the PreToolUse guard actually fires.** Four related fixes: (1) the GSD PreToolUse hook parsed only flattened Claude-style payload fields (`toolName`/`toolInput`), while Cline's documented hook payload nests the call under `preToolUse` — the `.planning/` guard silently never cancelled anything; the hook now reads `preToolUse.tool`/`preToolUse.parameters` first and keeps the flattened form as a fallback. (2) Local installs no longer hoist `targetDir` to the project root (`hostBehaviors.localTargetIsProjectRoot` retired): the gsd-core engine, `agents/`, `scripts/` and state files now live under `./.cline/`, and rules/hook move from the deprecated `.clinerules/` directory form to Cline's current `.cline/rules/gsd.md` + `.cline/hooks/PreToolUse`. (3) Global installs write rules/hook to `~/.cline/rules/` + `~/.cline/hooks/` instead of the never-read `~/.cline/.clinerules/`. (4) Local installs now also emit the `gsd-*` skills to `./.cline/skills/` (`artifactLayout.local` mirrors global) — Cline's current layout loads project-level skills, so `/gsd-*` commands exist as real skills locally instead of only via the rules file. On the next install, legacy artifacts are cleaned up automatically: manifest hash-matched root-level spill is deleted (user-modified files are kept), and only the GSD-managed files are removed from `.clinerules/`. `scripts/changeset/README.md` is now manifest-tracked so it uninstalls cleanly too.
